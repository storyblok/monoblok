# ADR-0029: Inlined Relations Become Non-Circular by Default in 1.0

**Status:** Accepted  
**Date:** 2026-11-20

## Context

With `inlineRelations: true`, `@storyblok/api-client` replaces relation UUIDs with the related
stories at any depth, and every reference to a story is the same object. Stories that reference each
other (A → B → A, or longer cycles) make the result circular. `JSON.stringify` throws on it, and so
does every framework feature that serializes data: Astro island props, server islands and content
layer loaders, Next.js Pages Router props, and caches such as `unstable_cache`. Since a shared story
serializes once per reference, the output can also grow exponentially with the depth.

`storyblok-js-client` never returns a circular result: it inlines relations two levels deep, and
relations below that stay UUIDs.

## Decision

`ContentApiClientConfig` gets a `circularReferences` option:

- `true`: the current behavior. Relations are inlined at any depth with one shared copy per story,
  so the result can be circular.
- `false`: the `storyblok-js-client` behavior. A related story referenced from a requested story has
  its relations inlined; relations inside it stay UUID strings. Copies are shared per story and
  level, so the result is acyclic and its size is bounded.
- Unset: behaves like `true`, and logs one warning per process the first time a result is circular.
  This default is deprecated.

`false` caches inlined results under a different cache key prefix than `true` and unset, so clients
with different settings can share a cache provider without serving each other's results.

In 1.0, the default changes to `false`.

## Consequences

- No type changes: relation fields are already typed `string | story`.
- Code that relies on relations deeper than two levels has to set `circularReferences: true`.
- Code that walks the result for identity (e.g. `related.content.related === story`) only works with
  `true`.
