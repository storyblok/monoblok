# ADR-0030: Inline Links Only as Deep as the API Resolves Them

**Status:** Accepted  
**Date:** 2026-11-20

## Context

`@storyblok/api-client` gained `inlineLinks`, which puts the stories from a response's `links` into
the content, as `storyblok-js-client` does. A first version inlined links inside linked stories at
any depth and shared one copy per story. Interlinked stories then serialized exponentially (12 pages
grew from 24 KB to 4 MB), and with `inlineRelations` on too, a linked story referenced twice whose
relations formed a cycle overflowed the stack.

## Decision

- `story` goes on the link itself (the multilink value, or a rich text link mark's `attrs`), so the
  link keeps `url`, `anchor` and `target`. Same place and key as `storyblok-js-client`.
- Links are inlined as deep as the API resolves them: the requested stories' links, and with
  `resolve_links_level: 2` the linked stories' links too. Each level only points to the next, so the
  result is never circular and links need no option for it. Copies are shared per story and level;
  the response's `rels` and `links` stay unchanged.
- Relations inside linked stories stay UUIDs, because the API doesn't resolve them; relation
  inlining skips a link's `story`.
- Links beyond the resolve limit (`link_uuids`) are fetched as stories. With `resolve_links: "url"`
  they're reduced to the url shape (`url` is `path`, or `full_slug` when `path` is empty), so
  `InlinedLink<"url">` is exact. With `"link"` they stay full stories, since `real_path` can't be
  derived from a story, and the type is a union.
- A failed follow-up request for `rel_uuids` or `link_uuids` returns an error result unless
  `throwOnError` is set, like any other failed request.
- Types follow the literal `inlineLinks` and `resolve_links`. `WithInlinedContent` takes an options
  object (`relations`, `links`, `fieldPlugins`) for props that combine both, instead of more
  positional parameters on `WithInlinedRelations`.
- `inlineLinks` and `inlineRelations` keep defaulting to `false`, also in 1.0.

## Consequences

- Links and relations follow one rule from 1.0 on (ADR-0029): inline what the API resolved, never
  circular. Until then, relations can still be circular by default.
- A `"link"` response past the resolve limit mixes link objects and stories, so consumers narrow.
- Code that mutates an inlined story changes every place that shares the copy.
