# ADR-0029: Inlined Relations and Links Are Not Circular by Default

**Status:** Accepted  
**Date:** 2026-11-20

## Context

`@storyblok/api-client` inlines relations (`inlineRelations`) and links (`inlineLinks`). Each
related or linked story is copied once and shared by every reference to it. When stories reference
each other (A → B → A, or A → B → C → A), sharing that copy makes the result circular.

A circular result works where data is serialized with React Flight or devalue (Next.js App Router
props, `"use cache"`, Astro actions), but throws wherever it is serialized as JSON:
`JSON.stringify`, Astro island and server island props, Astro content layer loaders, the Next.js
Pages Router, and `unstable_cache`. It only fails once an editor adds a back-reference, so it can
surface in production. `storyblok-js-client` never produced circular results.

Relations have always been circular, and code may rely on it.

## Decision

A `circularReferences` client option controls both. When `false`, a relation back to a story that is
still being inlined stays a UUID, and such a link gets no `story`. The types already allow both.

- Links default to `false`.
- Relations default to `true`, which is deprecated. A circular relation logs a warning until the
  option is set. The default changes to `false` in 1.0.

## Consequences

- New users of `inlineLinks` get output that every serializer accepts.
- Existing users of `inlineRelations` see no change until they opt in or 1.0 ships.
- Which reference to a story stays a UUID depends on traversal order, because each story is copied
  once and shared.
- Until 1.0, the two options default differently.
