# ADR-0030: Inlined Relations Are Never Circular from 1.0

**Status:** Accepted  
**Date:** 2026-11-20

## Context

With `inlineRelations: true`, `@storyblok/api-client` replaces relation UUIDs with the related
stories at any depth, and every reference to a story is the same object. Stories that reference each
other (A → B → A, or longer cycles) make the result circular. `JSON.stringify` throws on it, and so
does every framework feature that serializes data with it: Astro island and server island props,
`<StoryblokServerData>`, content layer loaders, Next.js Pages Router props, and `unstable_cache`.
Serializers that handle cycles, such as React Flight and devalue, work. Since a shared story
serializes once per reference, the output can also grow exponentially with the depth.

`storyblok-js-client` never returns a circular result: it inlines relations two levels deep, and
relations below that stay UUIDs.

## Decision

`ContentApiClientConfig` gets a `circularRelations` option. Links are never circular, so it only
affects relations.

- `false`: the `storyblok-js-client` structure. A related story referenced from a requested story
  has its relations inlined; relations inside it stay UUID strings. Copies are shared per story and
  level, so the result is never circular and its size is bounded.
- `true`: relations are inlined at any depth with one shared copy per story, so the result can be
  circular.
- Unset: behaves like `true` and logs one warning per process the first time a result is circular.
  This default is deprecated.

`false` caches inlined results under a different cache key prefix than `true` and unset, so clients
with different settings can share a cache provider without serving each other's results.

The option is a migration path for 0.x. 1.0 removes it, and relations always behave like `false`.
`inlineRelations` and `inlineLinks` keep defaulting to `false` in 1.0.

## Consequences

- No type changes: relation fields are already typed `string | story`.
- Code that needs relations deeper than two levels has to fetch them itself from 1.0 on; until then,
  `circularRelations: true` keeps the old behavior.
- Code that walks the result for identity (e.g. `related.content.related === story`) only works with
  `true`, and stops working in 1.0.
