# [Bug]: Wrong single-option field types

### Package

storyblok (CLI)

### Bug Description

We had a runtime issue, because a single-option field returned `""`, although the generated types
indicated that this is not a possible state.

That lead me to test how the config for the single-option field affects the UI and the types. The
crucial options were "Required" and "Hide empty option". Especially the behavior of the later one
was not clear to me.

### Steps to Reproduce

1. Create a component with eight fields:
   ```
   name: first
   options: { One: 'one', Two: 'two' }
   required: true
   hide empty option: false

   name: second
   options: { One: 'one', Two: 'two' }
   required: true
   hide empty option: true

   name: third
   options: { One: 'one', Two: 'two' }
   required: false
   hide empty option: false

   name: fourth
   options: { One: 'one', Two: 'two' }
   required: false
   hide empty option: true

   name: fifth
   options: { One: 'one', Two: 'two', Empty: '' }
   required: true
   hide empty option: false

   name: sixth
   options: { One: 'one', Two: 'two', Empty: '' }
   required: true
   hide empty option: true

   name: seventh
   options: { One: 'one', Two: 'two', Empty: '' }
   required: false
   hide empty option: false

   name: eighth
   options: { One: 'one', Two: 'two', Empty: '' }
   required: false
   hide empty option: true
   ```
2. Generate types with the storyblok CLI

### Expected Behavior

Generate types, which reflect the possible states of the JSON payload. I would expect types like
this:

```ts
export interface MyComponent {
  first: "one" | "two";
  second: "one" | "two";
  third: "one" | "two" | "";
  fourth: "one" | "two" | "";
  fifth: "one" | "two";
  sixth: "one" | "two";
  seventh: "one" | "two" | "";
  eighth: "one" | "two" | "";
  component: "HnnngTest";
  _uid: string;
}
```

### Actual Behavior

The generated types look like this:

```ts
export interface MyComponent {
  first: "" | "one" | "two";
  second: "one" | "two";
  third?: "" | "one" | "two";
  fourth?: "one" | "two";
  fifth: "" | "one" | "two";
  sixth: "one" | "two" | "";
  seventh?: "" | "one" | "two";
  eighth?: "one" | "two" | "";
  component: "HnnngTest";
  _uid: string;
}
```

This can lead to runtime issues, if you rely on the types being correct, especially with `??` for
fallbacks.

```ts
// Type is ('one' | 'two'), but the value is ''
const fieldValue = third.third ?? "one";
```

The key problems are:

- "Hide empty option" only affects the UI, so it should not have any impact on the types
- "Required" does not allow empty strings as valid field values, so you would never be able to save
  `""` as a value. It does not matter if there is a manually created empty-option, because the
  option is selected it behaves like clearing the field.
- Fields are never omitted from the json, when a field is empty while saving the story, it will
  always be set to `""`. My guess is that only conditional fields might be truly optional, but I was
  not able to check that, because I've used a fresh space on the free-plan for testing this, which
  does not support conditional fields.

### Additional Context

With this config, I only see one workaround for generating types that would let you avoid runtime
errors: You would need to never add an empty option manually and misuse "Hide empty option" to
control if `""` should be added to the types or not by keeping it in sync with the "Required"
config.
