# [Bug]: TDZ ReferenceError when Storyblok components have circular dependency through `StoryblokComponent`

### Package

@storyblok/astro

### Bug Description

When two registered Storyblok components form a circular dependency through
`StoryblokComponent.astro`, Vite 6's SSR bundler emits them into a single chunk with deferred
getters. Because the `virtual:import-storyblok-components` virtual module eagerly accesses
`.default` on every glob'd module at module initialization time, the deferred getter fires before
the target variable is initialized, producing a TDZ `ReferenceError`.

The cycle is: `Card.astro` imports `Richtext.astro`, which imports `StoryblokComponent.astro` (from
`@storyblok/astro`), which imports `virtual:import-storyblok-components`, which eagerly re-imports
`Card.astro` via the `import.meta.glob(..., { eager: true })` call and immediately reads
`modules[filePath].default` at the top level.

### Steps to Reproduce

1. Create two Storyblok components where one imports the other, and the second imports
   `StoryblokComponent` from `@storyblok/astro`:

   ```
   Card.astro → imports Richtext.astro
   Richtext.astro → imports @storyblok/astro/StoryblokComponent.astro
   StoryblokComponent.astro → imports virtual:import-storyblok-components
   virtual module → eagerly imports Card.astro (cycle)
   ```

2. Register both in `astro.config.ts`:

   ```ts
   storyblok({
     accessToken: "dummy",
     components: {
       card: "storyblok/Card",
       text: "storyblok/Richtext",
     },
   });
   ```

3. Create a page that renders `Card`.

4. Run `astro build`.

### Reproduction URL

https://stackblitz.com/github/adamchal/storyblok-tdz?startScript=build

### Expected Behavior

The build completes successfully. Circular component dependencies are a natural pattern in
CMS-driven sites (a Card can contain rich text, and rich text can contain embedded Storyblok blocks
via `StoryblokComponent`).

### Actual Behavior

The build fails during static generation with:

```
ReferenceError: Cannot access '$$Card' before initialization
```

### Additional Context

The root cause is in the generated `virtual:import-storyblok-components` module
(`vite-plugin-import-storyblok-components`). It does:

```js
const modules = import.meta.glob(".../storyblok/**/*.astro", { eager: true });
const storyblokComponents = {};
for (const filePath in modules) {
  const component = modules[filePath].default || modules[filePath]; // <-- TDZ here
  storyblokComponents[camelCaseName] = component;
}
```
