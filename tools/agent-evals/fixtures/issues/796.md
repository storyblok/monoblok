# [Bug]: `components push` silently drops `preview_tmpl`

### Package

storyblok (CLI)

### Bug Description

## Description

`storyblok components push` reports successful component updates but does not persist the
`preview_tmpl` property.

The Storyblok Management API supports `preview_tmpl`.

## CLI versions affected

- Global CLI used by the terminal: `storyblok@4.22.2`
- Project-local CLI: `storyblok@4.22.3`

Both versions contain the same omission.

### Steps to Reproduce

1. Pull component schemas as separate files:

   ```sh
   storyblok components pull --space=<space-id> --separate-files
   ```

2. Set a non-null preview_tmpl in a local component JSON file, for example:
   ```sh
   {
     "name": "InfoSlider",
     "preview_tmpl": "<div>My preview template</div>"
   }
   ```
3. Push the components:

```sh
  storyblok components push --space=<space-id> --separate-files
```

4. Pull the same component again into a different/empty directory:

```sh
  storyblok components pull InfoSlider --space=<space-id> --separate-files --path=<temporary-directory>
```

### Expected Behavior

## Expected behavior

The newly pulled component should contain the submitted preview_tmpl.

### Actual Behavior

## Actual behavior

The CLI reports success, for example: ✔ 58 updated 62 requests made

However, a fresh pull returns:

```sh
"preview_tmpl": null
```
